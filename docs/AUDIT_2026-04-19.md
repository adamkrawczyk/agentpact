## 2. Root Cause (strongly supported hypothesis)

### 2a. Synchronous audit writes on the browse hot path

`apps/api/src/routes/needs.ts:156` — every `GET /api/needs` **awaits** an `INSERT INTO audit_log` before returning:

```ts
// apps/api/src/routes/needs.ts:156
await auditBestEffort(app, sql, "browse.latency", "endpoint", null, { ... });
return rows;
```

Same pattern in `apps/api/src/routes/offers.ts:312, 387, 528, 544`.

Every browse request grabs a connection for the SELECT, **releases it, then grabs a second connection for the audit INSERT**, which blocks the response. Under pool pressure each browse takes two round-trips of wait time.

### 2b. `recomputeMatches()` is O(N×M) and fire-and-forget but uses the shared pool

`apps/api/src/index.ts:842` defines `recomputeMatches()` — it:

1. Selects all active offers (`apps/api/src/index.ts:843-848`)
2. Selects all open needs (`apps/api/src/index.ts:849`)
3. Nested-loops all pairs (`apps/api/src/index.ts:882-917`). With today's numbers that's **39 × 212 = 8 268 iterations**.
4. For each pair with tag overlap: one `INSERT ... ON CONFLICT DO UPDATE` into `matches` (`apps/api/src/index.ts:908-913`) — so potentially thousands of writes per call.
5. If `SEMANTIC_MATCHING_ENABLED=true`, it also calls `generateEmbeddings(allTexts)` via OpenAI first (`apps/api/src/index.ts:876`), and then `await computeSemanticScore(offerText, needText)` **inside** the double loop (`apps/api/src/index.ts:902`) — meaning the loop awaits a network call per pair.

It is invoked fire-and-forget from:
- `apps/api/src/routes/offers.ts:196` (POST /api/offers)
- `apps/api/src/routes/offers.ts:247` (PATCH /api/offers/:id)
- `apps/api/src/routes/needs.ts:69` (POST /api/needs)
- `apps/api/src/routes/needs.ts:108` (PATCH /api/needs/:id)

Because invocations are **not de-duplicated or queued**, two concurrent offer/need writes kick off two parallel 8k-iteration passes that compete for the same pool.

### 2c. Pool is `max: 20`

`apps/api/src/index.ts:85-90`:

```ts
export const sql = postgres(DATABASE_URL, {
  max: 20,
  idle_timeout: 30,
  connect_timeout: 10,
  max_lifetime: 1800,
});
```

`connect_timeout: 10` means a query waiting >10s for a free connection throws — but the browse handler does not set a **statement timeout**, so the first query that _did_ grab a connection can hold it for much longer while a background `recomputeMatches` pass holds the rest.

### 2d. Indexes are fine; this is not a missing index

`migrations/026_needs_status_created_at_index.sql` covers `/api/needs`.
`migrations/022_offer_compounding.sql:5` covers `offers(status, created_at DESC)`. Codex's audit note that this migration was missing is **incorrect** — it is present.
Trigram indexes 027–031 cover the ILIKE paths. Since `?limit=1` with no query also hangs, index quality is a non-issue.

### 2e. WIS-227 did land on `main`

Codex confirmed via GitHub fetch at commit `3b1dff64` that the blank-`query` short-circuit is present: `search` is empty, so the ILIKE branch is skipped. This fix is deployed; the hang has a different cause (2a + 2b).

**Conclusion:** `/api/needs` hangs because incoming browse traffic is contending with unbounded, unqueued, recurring `recomputeMatches()` passes that consume the pool; the browse handler then blocks on a synchronous audit write while the pool is saturated.

## 3. Security Findings

### 3a. Admin routes fail-open when `ADMIN_API_KEY` unset
`apps/api/src/routes/admin.ts` — `checkAdminKey()` allows access if the env var is undefined. In an ops rotation or a fresh Railway deploy where the secret is not yet set, admin is exposed.

**Fix:** always deny when `ADMIN_API_KEY` is empty; refuse to boot the server in production with `NODE_ENV=production && !ADMIN_API_KEY`.

### 3b. Public GET bypass is too broad
Anonymous GET appears to reach `/api/deals/:id` and list endpoints (verified via route inspection), which can trigger consultation auto-completion side effects. **Fix:** require API-key auth on deal reads; at minimum filter by participant.

### 3c. Input validation gaps on browse
- `boundedInteger()` handles `limit`/`offset` but the `tags` param is split naively and unbounded: `q.tags.split(",")` — an attacker can pass 10 000 tags and bloat the `tags && ${tags}` array comparison. Cap to e.g. 20 tags ≤ 64 chars each.
- `query` length uncapped — cap at 200 chars to keep ILIKE planner happy.

### 3d. Idempotency-key collisions
`audit()` uses `idem = metrics:${action}:${Date.now()}` (routes/needs.ts:36). Under millisecond-level concurrent POST bursts this can collide and fail the unique constraint. **Fix:** include a random suffix or use the HTTP header `Idempotency-Key` where present.

### 3e. SSRF risk in `autoVerify()` unreviewed
Fulfillment flow calls outbound URLs per deal. Need to confirm we block private networks (10.*/172.16/192.168/169.254) and non-HTTPS.

### 3f. No SQL injection risk detected
All queries use the `postgres.js` tagged-template interface correctly. ✅

### 3g. Route deduplication ✅
`bash scripts/lint-routes.sh` → "No duplicate routes found". The WIS-82 footgun is closed.

## 4. Frontend

`apps/web/src/index.ts:710-737` — `needsHandler` fetches `/api/needs` with `AbortSignal.timeout(8000)` (`:341`). Any API response >8s returns `[]` via `getJsonWithFallback`, which renders **"No needs available right now"**. This exactly matches what users see today.

Additionally the web worker renders the whole page **before** responding (Fastify `reply.send` waits for `getJson` to settle). At 8.6s TTFB that's below the frontend's internal 8s abort — but the user sees a rendered page, just with the empty-state text.

**UX fix:**
1. Decouple the list from the page shell: render the shell immediately, fetch needs client-side or via streaming.
2. Cache last-known-good needs list in memory with 30s TTL; serve stale-while-revalidate.
3. Replace "No needs available right now" with "Marketplace temporarily unreachable — retry in 30s" when the warning string is set. The message is already plumbed through `warning`; it just isn't shown in the needs branch (`apps/web/src/index.ts:727-734`).

## 5. Prioritized Fixes

### P0 — ship today to stop the bleed

1. **Drop `await` on browse audit writes**
   - `apps/api/src/routes/needs.ts:156`
   - `apps/api/src/routes/offers.ts:312, 387, 528, 544`
   - Change `await auditBestEffort(...)` → `void auditBestEffort(...).catch(err => app.log.warn({err}, "audit insert failed"))`.
   - ≈ 10 LoC total. Removes the second-connection grab on every browse response.

2. **Add statement timeout on browse endpoints**
   - At `apps/api/src/routes/needs.ts:125` and `offers.ts:263`/`413`, run the query under `SET LOCAL statement_timeout = 4000` inside a `sql.begin(...)`.
   - 4s caps the browse worst-case well under the 8s frontend abort.
   - ≈ 30 LoC.

3. **Single-flight queue for `recomputeMatches()`**
   - Add a module-level `let inFlight: Promise<number> | null = null; let dirty = false;`
   - Callers set `dirty = true` and return immediately. A worker checks every 5s: if `dirty && !inFlight`, it runs the recompute, then resets.
   - File: `apps/api/src/index.ts` around `:842`. ≈ 40 LoC.
   - Also rate-limit with `p-limit(1)` on the pair loop so we can't stack two passes ever.

**Estimated impact:** P0 fixes collapse the pool contention and cap every browse at ≤4s. Frontend timeouts disappear.

### P1 — within a week

4. **TTL cache on `/api/needs` and `/api/offers`**
   - 30s LRU keyed by `(endpoint, limit, offset, query, tags.sort().join(','))`.
   - ≈ 60 LoC. Eliminates the hot path almost entirely for anonymous traffic.

5. **Frontend: show warning in the needs empty-state**
   - `apps/web/src/index.ts:727-734`. Plumb `warning` through and render "Marketplace temporarily unreachable, refreshing…" instead of the hard-negative "No needs available". ≈ 15 LoC.

6. **Admin fail-closed**
   - `apps/api/src/routes/admin.ts` — deny all requests when `ADMIN_API_KEY` is empty; crash the process on boot in `NODE_ENV=production`. ≈ 20 LoC.

7. **Cap `tags` and `query` length on browse**
   - `apps/api/src/routes/needs.ts:132` and `offers.ts` similar. ≈ 15 LoC.

### P2 — next sprint

8. **Require auth on deal reads** (`/api/deals`, `/api/deals/:id`) — filter by participant. ≈ 60 LoC.
9. **SSRF hardening in fulfillment autoVerify** — block private-network URLs, enforce HTTPS. ≈ 100 LoC.
10. **Idempotency-key collision fix** — use `Idempotency-Key` header with random suffix fallback. ≈ 15 LoC.
